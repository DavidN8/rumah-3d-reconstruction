Description:
  Runs extract -> match -> map -> merge with COLMAP's automatic_reconstructor presets and writes
  WORKSPACE/{features,matches.bin,sparse/0}. A capture that is not one connected view graph also
  writes sparse/1, sparse/2, ... -- the remaining components, largest first.

  The positional defaults to `images`; a dataset directory containing `images/` is accepted and
  that sub-directory used, so `auto DATASET` and `auto DATASET/images` behave the same. `masks`
  beside the image directory is picked up automatically.

  Two knobs decide the rest: --quality and --data-type. Anything they set can be overridden by
  naming the flag explicitly, and the run reports what they moved.

Options:
  -o, --output DIR                        [required]
      Workspace to write: features/, matches.bin and sparse/0.. land in it.
  --manifest FILE
      Read the capture's description from FILE (YAML or JSON): where the images and masks are,
      how the cameras are grouped, each group's lens and focal length, the rigs the lenses form,
      and the videos whose IMU and GPS cover them. A flag on the command line beats the file.
  --rig [KIND=]PREFIX,PREFIX,...
      Images under these path prefixes with the same name are one rig frame and keep a fixed
      relative pose (cam0,cam1 pairs cam0/x.jpg with cam1/x.jpg). Repeat for several rigs; the
      manifest's `rigs:` can also carry known extrinsics. A `dual-fisheye=` prefix says the
      first two are the back-to-back lenses of one 360 camera.
  --sequence PREFIX[,PREFIX...]
      Images under these path prefixes were taken in file-name order (a video's frames, a folder
      shot in a walk). Their neighbours are matched, and the mapper trusts a neighbour's
      correspondences before any other, which keeps repeated structure from folding the model
      onto itself. Images with the same name under two members share a position, so a rig's
      lenses are one sequence (cam0,cam1). Repeat for several sequences; `.` is the image
      directory itself.
  --no-masks
      Ignore a masks directory even if one is sitting beside the images.
  --no-manage
      Skip merging, growing, reseeding and splitting, keeping the mapper's raw models.
  --progress-dir DIR
      Write snapshots of the run into DIR while it goes -- the current model and the pair matrix
      -- for a front end that is watching. Off by default; the graphical interface passes it to
      its own child.
  -h, --help
      Show this help and exit.

 pipeline:
  --quality {low|medium|high|extreme}     [high]
      Working resolution, feature budget and pair-selection breadth
  --data-type {individual|video|internet} [individual]
      What the capture is: individual photos, video frames, or an unordered internet collection
  --pairs VALUE                           [auto]
      Which image pairs are matched; auto is GPU pair selection at 100 images or more,
      sequential (plus loop closure) for video below that, and exhaustive otherwise (one of:
      auto exhaustive sequential prefilter)
  --overlap N                             [10]
      Neighbours each image is paired with under --pairs sequential and along a --sequence, and
      how far apart two images of a sequence still count as neighbours in mapping
  --no-loop-closure                       [on]
      Under --pairs sequential, also match the content-similar pairs GPU pair selection finds,
      so a capture that revisits a place links back to it
  --quadratic-overlap                     [off]
      A sequential window also pairs each image with the ones 16, 32, 64 ... apart in file
      order, up to 2^(overlap-1), as COLMAP does
  --prefilter-sequential                  [off]
      When GPU pair selection runs, also match each image with its neighbours in file order
      within its folder (the sequential window, --overlap and --quadratic-overlap), so a real
      link the content score ranked too low is not lost
  --no-rig-pairs                          [on]
      On a dual-fisheye rig, match each verified pair's rig-mates too: when cam0 of two frames
      matched, cam1 of the same two frames; when cam0 matched cam1, the camera had turned round,
      so cam1 against cam0
  --rig-pair-angle X                      [30]
      How far apart, in degrees, two rig-mates' viewing directions may be for --rig-pairs to
      match them
  --rig-pair-min-inliers N                [30]
      Inliers a verified pair needs before --rig-pairs matches its rig-mates
  --max-error X                           [3]
      Inlier radius for verification and mapping, in pixels of the image SIFT ran on rather than
      of the source file (D47)
  --max-image-size N                      [0]
      Longest edge the extractor runs on; larger images are downscaled first, and keypoints are
      still reported in the source image's pixels. 0 picks the frontend's own default (3200 for
      sift, 1600 for aliked)
  --masks DIR                             [none]
      Directory of masks; keypoints on zero (black) pixels are dropped. auto defaults it to
      `masks` beside the image directory
  --flip-mask                             [off]
      Swap keep and ignore in every mask, for the exporters that paint the region to REMOVE
      rather than the region to keep
  --feature-masks DIR                     [none]
      A second directory of masks, intersected with --masks: keypoints are kept only where both
      are nonzero. For what the reconstruction should not use but training should, such as the
      sky. Never flipped
